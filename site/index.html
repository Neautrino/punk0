Coding agents in tabs. The diff beside them.

punk0 is one Go binary that runs Claude Code, Codex and OpenCode in real terminals, gives every task its own git worktree, and keeps the changed files and a full editor in the same browser tab.

The punk0 way

punk0 keeps it simple. It organises the agents you already run and shows you their work.

By hand todayWith punk0
A terminal window per agent, gone when it closes.
Tabs run inside punk0. Close or reload the browser and they keep running, then replay their recent output.
git worktree add by hand, cleanup later.
New workspace makes a worktree on its own branch under ~/.punk0. Deleting the workspace can remove the folder with git worktree remove.
Checking every terminal for an agent that is waiting.
The status bar counts agents that need you or are working, and the page title shows how many wait. Desktop notifications if you turn them on. Claude Code tabs report this through its hooks.
Opening the diff in another tool.
The changed files and their diff sit beside the terminal, and the full editor is one click away.
Which chat was that?
Chats lists the conversations Claude Code, Codex and OpenCode keep on disk, including ones started in another terminal, and resumes any of them in a tab.

One binary

Written in Go. No Electron, no Node, no cgo.

The real CLIs

Each agent is the unmodified CLI started in your shell, signed in as you. punk0 has no chat of its own.

Local

Listens on 127.0.0.1. Terminals are refused if it listens anywhere else, and requests from other host names are rejected.

Out of your repo

State lives in ~/.punk0. Repositories only get worktree registrations, and temporary refs/px0/* during a review.

Small on purpose

Other orchestrators are desktop apps that bring their own browser engine, a background daemon, and sometimes a chat pane and a sign-in. punk0 does one job, organising the agents you already run, and leaves the rest out.

Same job for each app: the flask repository as a project, one git worktree, two idle shell tabs. Median of 3 runs on one Linux machine (Ryzen 5 5600H, 22.8 GiB RAM), measured 2026-10-26. Memory is PSS of every process the app started, shells excluded. punk0 has no browser of its own, so its row charges it for a whole Chrome running only its tab; in a browser you already have open, the tab costs about 112 MiB. How it works

punk0 runs on your machine and serves one page at 127.0.0.1:7777. Everything hangs off three things.

  1. Projects

    A repository you add with punk0 ~/code/app. A second punk0 hands its folder to the one already running.

  2. Workspaces

    The project folder, a git worktree on a branch of its own, or a scratch folder for work with no repository.

  3. Tabs

    Your shell in a terminal, or an agent started in it: Claude Code, Codex, OpenCode, Antigravity or Cursor Agent.

Tabs outlive the page

Reload and every tab reattaches with its recent output. Restart punk0 and a Claude Code tab resumes its own conversation.

A terminal idle for 30 minutes is stopped, never a Claude tab that is working or waiting. A folder's editor stops after 5 idle minutes and starts again on the next request.

The agent beside your code

Every folder opens in a full editor with the workspace's terminals on its right. Select lines and hand them to an agent without copying anything.

Ctrl/Cmd+K Quick Edit
Runs your coding agent once on the selected lines, in an empty temporary folder, and shows the result as a diff. Accept writes it only if those lines still read as they did.
Alt+L Add to Chat
Pastes @path lines a-b and the code into the agent in the active tab, without pressing Enter.
Alt+C Copy Ref
Copies path:start-end to paste into any chat.

Pull request review

punk0 <pr-url> checks the PR out as a worktree of your clone and diffs it against the merge base. GitHub, GitLab, Gitea and Bitbucket; comments, verdicts and merging with a token, read-only without one. Batch Apply hands the comments to your agent.

Build it

punk0 is early, and no release is published yet. Build it from source with Go 1.25 or later and Bun.

Once a version is tagged, the release workflow publishes binaries for Linux, macOS, Windows and the BSDs, and install.sh downloads the right one.
